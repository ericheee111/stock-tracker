# 用户交易画像与多周期产品设计

> **实现范围补充（2026-09-11）：** 本轮已完成P1–P3的有限手工计划候选，详见 `MULTIHORIZON-P1-P3-IMPLEMENTATION.md`；下文更广的策略、真实执行与数据语义设计并未全部实现。主周期保持用户确认，原风险阈值与信号算法未改。

日期：2026-09-11。状态：**USER_PROFILE_CONFIRMED / MANUAL_P1_P3_IMPLEMENTED / STRATEGY_AND_FILL_LAYERS_PENDING**。

本文件记录用户明确需求与据此形成的设计；人工计划UI已有限实现，算法、券商账户能力和真实成交层仍未实现，也不宣称任何策略最优。与既有规范冲突时，仅替换产品画像、周期重点和首页优先级；数据、安全、PIT、权限及自动交易限制不变。

## 1. 用户已经确认，不再重复询问

- 主要交易方式：几周到几个月的波段。
- 波段持有期间会做 T；另有部分长持和短线。
- 管理已有持仓和发现新机会都必须是主功能，不做二选一。
- 本轮没有授权改变账户风险比例、自动下单或启用任何 Broker/XTP 写接口。

原 PRD 的“A 股主要为 1—20 个交易日”不再是当前主画像。短周期继续支持，但不能限制波段主线；持有月份也不能按固定自然日与交易日互换。A 股优先、港股通第二、美股第三保持；不同市场依旧使用各自的数据、交易规则与验证。

## 2. 三类持仓目的，做 T 是附加操作层

| 持仓目的 | 用户目标 | 设计上的主要判断 | 禁止混淆 |
|---|---|---|---|
| SWING：波段主仓 | 几周到几个月的趋势与波段 | 周/日级趋势、相对强弱、催化、回撤与结构失效 | 不由一分钟噪声直接改写原计划 |
| LONG_TERM：长持 | 更长期逻辑与持续跟踪 | 经营/事件/估值变化、长期趋势及组合风险 | 短线失败不能自动改成长期投资 |
| SHORT_TERM：独立短线 | 少量短周期机会 | 单独的入场、退出、时效与成本条件 | 不借用波段仓止损和风险预算 |
| T_OVERLAY：做 T 操作层 | 在既有持仓约束内改善执行 | 可卖数量、资金、盘中结构、净成本、敞口偏离 | 不是第四份独立资金池，不默认等于可当日回转的新品种 |

同一证券可以有多个虚拟持仓分组，但账户真实总仓位、可卖量、现金与风险只有一套事实来源。分组数不能增加可交易额度。T 计划必须引用 parent_plan_id / sleeve_id；默认只使用用户明确分配的机动数量，不自动动用长持核心数量。

保留 UNCLASSIFIED 兼容旧持仓，要求用户逐步补充目的；不按盈亏猜测其策略，不删除旧记录。分组重新归类必须有记录时间及原因，不回写旧绩效归属。

## 3. 持有、观察和执行分开建模

每个计划至少区分 intended_holding_horizon、signal_timeframe、review_cadence、entry_window、invalidation_policy、execution_rule_id。长周期计划可以有盘中触发，但盘中做 T 的失败不自动代表波段逻辑失效。

设计候选而非已验证参数：波段优先周/日级背景，以 20/40/60 个交易日等窗口做独立研究对照，允许更长窗口；短线另设 1/3/5/10 日候选；T 用独立日内事件窗口。用户并未指定这些数值，不能直接写入生产配置、复用已校准概率或把窗口到期视为强制清仓。

优先检查旧信号半衰期、过期机制、动态重算触发价、研究标签与收益统计是否默认短周期。计划创建后冻结依据、触发与失效语义；修订生成新版本，不能用后来价格移动门槛再宣称过去应该成交。

## 4. 做 T：先解决库存与计划，不先堆指标

首期仅提供手工计划、提示、成交记录和复盘。支持“先卖可卖旧仓再买回”和“先买后卖可卖旧仓”两个方向；后者不得把当日新买量直接当成新增可卖额度。不得产生裸卖空、融资、隐式杠杆或自动报单。

输入至少需要：account_id、instrument_id、total_quantity、sellable_quantity、quantity_as_of、quantity_source、today_bought/sold、reserved_sell_quantity、available_cash、parent_plan_id、可动用数量上限、核心保留数量、费用假设、数据新鲜度、有效交易时段与规则版本。

每份数量快照必须声明是否已扣除未成交委托；快照之后的真实成交/预留只应用一次，防止重复扣减或重复使用余额。没有券商接入时采用人工确认的来源与时间，标记 MANUAL_UNVERIFIED；缺失或过期可卖量时暂停具体 T 股数建议，不阻止查看行情、管理持仓或记录手工操作。

风险检查按账户+证券统一计算，所有持仓分组和并行计划共同扣减额度。先买后卖要计算中途峰值仓位与现金消耗，不能只看预期结束仓位。先卖后买要显示卖飞/未买回的剩余缺口；不得保证可以按目标价补回。

T 操作允许 NO_TRADE。净优势不足、趋势单边、行情不可靠、库存不明确、波段逻辑失效时，可以建议不做 T。取消/部分成交/另一腿未完成均保留真实状态；不能为“做成一轮”强制买回，也不能把失败 T 自动变成新波段计划。

## 5. A 股规则边界与时间有效性

已核对上交所《交易规则（2026年修订）》：2026-07-06 起施行，第 3.1.4 条区分交收前不得卖出与允许回转交易的品种，第 3.1.5 条列明回转品种。产品不得把普通 A 股做 T 解释为放开当日新买股票的卖出限制；一般的底仓做 T 需用实际可卖旧仓支持相应卖出。

规则按 instrument + venue + security_type + effective_from 解析，不把所有 A/HK/US 证券或所有 ETF 写成同一制度。特殊证券、不同板块、手数、申报单位、停牌、费用和资金可用性需分别核验；本轮没有完成全市场规则审计。

来源（2026-09-11 核对）：上海证券交易所，上证发〔2026〕41号，规则第 3.1.4—3.1.5 条及生效通知：
https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml

不能由“交易规则文档有效”推断某账户某时刻的库存可用，也不能用客户端时区替代交易所时区。

## 6. 首页双主线，不把一个功能藏起来

桌面：共同的市场/数据/账户风险摘要下，持仓管理与新机会发现并列；做 T 放在相应持仓卡和聚合待办里，不吞并新机会榜单。移动端：首屏同时出现两个摘要/计数与可达入口，详细卡片分组，不用大量持仓卡把新机会推到页面末尾。

| 持仓侧 | 新机会侧 |
|---|---|
| 波段/长持/短线目的与计划版本 | 波段机会优先，长线观察、短线单独分组 |
| 核心仓保持/失效/减仓条件 | 当前可关注、等待回踩、等待突破、回避 |
| 今天的 T 条件、可动用量与未完成腿 | 行业主线、相对强弱、催化与反方证据 |
| 组合风险、下一复核时点 | 3—5 个重点候选；不够就如实少展示 |

紧急风险和数据故障可置顶，但“风险置顶”不是“持仓永久压倒机会发现”。同一证券已持有时，新信号标为持仓内加减仓/观察，不重复占两个无关机会席位；两个区域可保留互相链接。

示例文案仅为设计：同一股票可同时显示“波段主仓：继续持有，观察日线结构”和“T 操作：今日暂无足够净优势”；不能只给一个相互覆盖的买/卖徽章。

## 7. 指标、算法和收益口径按任务分开

波段候选特征：周/日趋势质量、个股相对市场与行业强弱、板块广度、突破保留与回踩质量、波动尺度、成交参与度及事件催化。它们是待验证的输入族，不逐个重复计票，也不靠参数名称宣称 alpha。

T 候选特征：可信盘中价格/量、价差与流动性、时段条件、趋势/震荡状态和费用后的空间。VWAP 等需要明确成交价量来源与累计口径，不能从累计快照重复求和。真实数据不够时不输出伪精确 T 价或胜率。

长持与短线分别有自己的假设、失效与评价周期；短线评分不能用于强制退出长持核心仓。安全阻断与真正的长期逻辑失效仍可越过日常复核频率，不因“长持”而被忽略。

T 评价必须与同起点、同资金流、同估值时点的“不做 T 持有”基线比较。建议账本表达为：

    T 增量贡献 = 实际现金及持仓净值 - 同条件持有基线净值

两边使用相同价格/币种/公司行为口径，实际侧计入全部费用；保留未完成腿的现金与剩余持仓。不能只报已经配对的盈利价差，不得把失败未配对腿隐藏；不能再把已包含于净值差的踏空损失重复扣一次。

分别展示实际损益、做 T 配对差价、相对持有增量、周转成本、峰值敞口、未完成腿及长期趋势持有质量。“摊薄成本价”不自动等于账户净值增加，T 交易次数也不增加波段独立样本数。

## 8. 数据与工程推进顺序

1. 画像/计划/真实仓位的兼容设计与反例：先区分计划目的、库存、虚拟分组、T 附加计划；保留旧持仓。
2. 双主线首页与计划说明：可用合成 fixtures 验收，不先生成未经验证的交易价或概率。
3. 多周期策略基线：冻结指标方法、旧策略行为和周期身份，审查信号可达性与失效机制；再做样本外比较。
4. T 手工计划及记账：先验证数量、资金、成本、部分成交、日终未完成腿与相对持有归因，再评估提示算法。
5. B1d 真实物理语义 ReadPort → B2 Path → B3 Collection 与相关人工执行证据并行接通；真实多交易日与 4H/4I 仍按既定门禁。

不需要为了几个月的波段预先解决全市场 Level 2 高频采集。盘中资源优先给实际持仓、明确 T 计划和接近触发的少量候选；历史覆盖、复权、财务/事件可用时间不能被实时刷新频率替代。

## 9. 首批验收反例

| 场景 | 必须结果 |
|---|---|
| 波段持有超过 20 个交易日，逻辑未失效 | 不因旧全局上限自动到期/清仓 |
| 长持核心仓遇到分钟级卖出提示 | 不自动退出核心仓 |
| 同一股有两个虚拟分组 | 总数量/风险不能重复累加 |
| 两份 T 计划争用同一可卖量 | 预留后不能超卖 |
| 当天买入后无其他可卖旧仓 | 不产生可卖新股建议 |
| 可卖量仅有过期人工值 | 明确不可验证，不输出具体可执行股数 |
| 先买后卖未完成第二腿 | 显示峰值与额外隔夜敞口 |
| 先卖后买时波段逻辑失效 | 可以取消买回，保留偏离记录 |
| 价差为正但费用后或相对持有为负 | 不记为 T 改善 |
| 只有一笔盈利腿，亏损腿未配对 | 不展示已完成盈利一轮 |
| 新计划与现有持仓同时存在 | 首页两条主线都可达，不互相覆盖 |
| 旧样本/概率是短周期训练结果 | 不换标签冒充几个月波段概率 |

状态判断仅为规划；上述验收还没有由本次文档更新执行。资金比例、T 最大数量、具体持有期限和模型参数保留可配置，不把建议数值写成用户已确认的参数。自动下单仍为 false。
